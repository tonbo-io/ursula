<ParamField path="bucket" type="string" required>
 Bucket ID.
</ParamField>

<ParamField path="stream" type="string" required>
 Stream ID within the bucket.
</ParamField>

<ParamField header="Content-Type" type="string" required>
 Must match the stream's content type (set when the stream was created with `PUT`) after normalization: parameters are trimmed, lowercased and joined with `; `. Required when the body is non-empty. A mismatch returns `409`.
</ParamField>

<ParamField header="Stream-Closed" type="string">
 Set to `true` to close the stream after this append.
</ParamField>

<ParamField header="Stream-Seq" type="string">
 A compare-and-set token. The append is accepted only when the value is bytewise greater than the last `Stream-Seq` accepted on this stream; it is then stored. An equal or smaller value answers `409` with `Stream-Next-Offset` at the tail. Without the header the append is not checked and the stored value is unchanged. At most 256 bytes. See [Stream-Seq](#stream-seq).
</ParamField>

<ParamField header="Producer-Id" type="string">
 Stable producer identity (UUID, hostname, etc.) for [exactly-once writes](/docs/concepts/exactly-once-writes). Dedup state is per-stream. At most 256 bytes.
</ParamField>

<ParamField header="Producer-Epoch" type="string">
 Producer epoch. Bumped on producer restart. Must be ≥ the last epoch the server accepted for this `Producer-Id`. A new epoch resets the seq counter. Max value `2^53 − 1`.
</ParamField>

<ParamField header="Producer-Seq" type="string">
 Producer sequence number. Starts at `0` for a new epoch and must increase by exactly `1` per append. Exact `(epoch, seq)` duplicates are silently deduplicated. Max value `2^53 − 1`.
</ParamField>

<ParamField header="Stream-Record-Match" type="string">
 For JSON streams with Record Coordinates, require the current record tail to equal this ordinal. A mismatch returns `412` with the current `Stream-Record-Next`.
</ParamField>

<ParamField body="body" type="binary" required>
 The bytes to append. Must not be empty unless `Stream-Closed: true` is set (close-only request).
</ParamField>

## Response

| Status | Meaning |
| ------ | ------------------------------------------------------------------ |
| `204` | Append successful (default success response, no body). |
| `200` | Append successful with body - returned when a `Producer-Id` was supplied and the append was not deduplicated, so the response carries producer ack headers. |
| `400` | Empty body without `Stream-Closed: true`, missing content type, invalid JSON or UTF-8, a JSON message nested deeper than 127 levels, or a `Producer-Id` or `Stream-Seq` longer than 256 bytes. |
| `404` | Stream not found. |
| `409` | Content type does not match the stream, stream is already closed, `Stream-Seq` not greater than the stored value, or `Producer-Seq` out of order. |
| `412` | `Stream-Record-Match` did not match the current JSON record tail. |
| `413` | Body larger than 32 MiB. |
| `503` | Cold-write backpressure. Retry after the duration in `Retry-After`. |

Response headers include `Stream-Next-Offset` (always). When a `Producer-Id` was supplied, the server echoes the accepted `Producer-Epoch` and `Producer-Seq` so the producer can confirm what was durably recorded. `Stream-Closed: true` is set if this request closed the stream. `ETag` is set on reads only, not on appends.

For an `application/json` stream advertising `json-record-coordinates-v1`, the response also includes `Stream-Record-Start` and `Stream-Record-Next`. A JSON object creates one record, and a top-level array creates one record per element. The returned half-open range identifies exactly the records created by this request.

<RequestExample>
```bash Append binary
curl -X POST http://127.0.0.1:4437/demo/hello \
  -H 'Content-Type: application/octet-stream' \
  --data-binary 'hello world'
```

```bash Append JSON
curl -i -X POST http://127.0.0.1:4437/demo/hello \
  -H 'Content-Type: application/json' \
  --data-binary '{"captured_at":"2026-07-18T10:30:00.100Z","event":"click"}'
```

```bash Append multiple JSON records
curl -i -X POST http://127.0.0.1:4437/demo/hello \
  -H 'Content-Type: application/json' \
  --data-binary '[{"event":"click"},{"event":"navigation"}]'
```

```bash Close a stream
curl -X POST http://127.0.0.1:4437/demo/hello \
  -H 'Stream-Closed: true'
```
</RequestExample>

## JSON message text

Ursula validates every JSON body and stores each message as you wrote it, minus insignificant whitespace (spaces, tabs and line breaks outside strings), followed by one LF. Member order, duplicate members, number spelling such as `1.50e3` or `1e400`, and string escapes, including escapes of unpaired surrogates, are kept byte for byte, and every read returns that text. A top-level array is split into one message per element. A message may nest at most 127 levels. See [JSON message text](/docs/specs/extensions#json-message-text). Releases before this rule re-serialized messages; see the [release notes](/docs/release-notes).

## Stream-Seq

`Stream-Seq` is the base protocol's writer sequence, and Ursula enforces it per stream as a compare-and-set:

- The comparison is bytewise, so `"10"` sorts before `"9"`. Use fixed-width values, such as counters zero-padded to 20 digits.
- The scope is the stream, not a writer: every append that carries the header is compared with the last value accepted on that stream, whoever sent it.
- A rejected append commits nothing. Its `409` carries `Stream-Next-Offset` at the current tail, so the writer can read only what it missed.
- Producer deduplication runs first: a retry of an accepted `(Producer-Id, Producer-Epoch, Producer-Seq)` is answered as a duplicate with its original `Stream-Next-Offset`, not `409`. A `409` from `Stream-Seq` uses up no `Producer-Seq`.
- A creating [`PUT`](/docs/api/create-stream) stores its `Stream-Seq` as the starting value.

To let several writers extend one log, each validating against all of it, read to `Stream-Up-To-Date: true` and send the number of events read as `Stream-Seq`. See [Conditional writes](/docs/concepts/conditional-writes) for that pattern and for publishing committed facts.

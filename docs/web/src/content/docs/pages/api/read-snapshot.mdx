---
title: Read snapshot
api: "GET /{bucket}/{stream}/snapshot/{offset}"
---

`GET /{bucket}/{stream}/snapshot/{offset}` returns the snapshot blob at a specific offset. To read the latest snapshot, take its offset from the `Stream-Snapshot-Offset` header of [`HEAD`](/docs/api/head-stream).

<ParamField path="bucket" type="string" required>
 Bucket ID.
</ParamField>

<ParamField path="stream" type="string" required>
 Stream ID.
</ParamField>

<ParamField path="offset" type="string" required>
 Snapshot offset: the 20-character zero-padded decimal token returned by previous reads or `Stream-Snapshot-Offset` headers.
</ParamField>

| Status | Meaning |
| ------ | -------------------------------------- |
| `200` | Snapshot blob returned. |
| `307` | In a cluster, this node is not the stream's group leader. `Location` is the same request on the leader. |
| `404` | Stream, snapshot, or offset not found. |
| `502` | The snapshot body is in the cold tier and could not be read. |
| `503` | The group has no known leader, or the leader could not confirm its leadership in time. Retry after `Retry-After`. |

Response headers include `Content-Type`, `Content-Length`, `Stream-Next-Offset`, `Stream-Snapshot-Offset`, `Stream-Snapshot-Digest`, and `Stream-Up-To-Date: true` when the snapshot offset is the stream's tail. A body stored in the cold tier is streamed from it.

<RequestExample>
```bash Read specific offset
curl 'http://127.0.0.1:4437/demo/hello/snapshot/00000000000000000042'
```
</RequestExample>

<Note>
Snapshot reads are served by the group's leader after it confirms with a majority of voters that it still leads, so the read reflects every snapshot publish acknowledged before the request. A follower answers `307` to the leader; follow the redirect. See [Durability and consistency](/docs/concepts/durability-and-consistency#consistency).
</Note>

<Info>
See [snapshots](/docs/concepts/snapshots) for the snapshot lifecycle.
</Info>

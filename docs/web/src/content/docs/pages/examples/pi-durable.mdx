Pi Durable harnesses persist their sessions, tasks and conversations through a 17-method `Storage` contract. `@tonbo-io/pi-durable-ursula`, in [`clients/pi-durable-ursula`](https://github.com/tonbo-io/ursula/tree/main/clients/pi-durable-ursula) of the Ursula repository, implements that contract on a [keyed stream](/docs/concepts/keyed-streams), so one Ursula cluster is the harness's only store: log, query state and session catalog.

The mapping is direct:

- One Pi harness is one keyed stream, `/{bucket}/{harness_id}`, created with `Content-Type: application/json; profile=keyed-batch-v1`.
- One Pi commit is one `keyed-batch-v1` record, appended with `Stream-Record-Match: N`. Pi's `Seq` is the record ordinal `N`.
- Reads go to the [keyed-state](/docs/api/keyed-state) resource and are merged with the commits the owner has not seen indexed yet, so steady-state reads are served from the owner's memory.
- The log is never trimmed. Session metadata lives in [stream attributes](/docs/api/stream-attrs), and [`GET /{bucket}/streams`](/docs/api/list-streams) lists sessions.

## What the cluster needs

1. Every node runs a release that supports feature level 1, and the level is raised: `ursulactl cluster enable-feature --level 1` ([Operations](/docs/operations#feature-levels)). Below it, creating the keyed stream answers `409`.
2. A keyed-state indexer, with `server.keyed_state_upstream` pointing at it on every node ([Deploy](/docs/deploy-cluster#optional-keyed-state-indexer)). Without one the owner still works, but replays the whole log into memory at every open.
3. Room for a 32 MiB commit. A Pi commit can be as large as the 32 MiB request limit, and it must fit the per-group admission caps, `raft.max_uncommitted_size_per_group` and `storage.cold.max_hot_size_per_group`. Use the `standard` or `large` preset, or set both caps to at least 64 MiB; `tiny` and `small` are too small. Until a release supports feature level 3, also keep `runtime.external_payload_min_size` above 32 MiB so commits are never staged as external payloads.
4. No retention on harness streams. Keyed state is built from the full log.

## Install and run

The package is not published to npm yet. Use it from a checkout of the repository (Node.js 22.19 or later):

```bash
cd clients/pi-durable-ursula
npm ci
npm run typecheck
npm test
```

To run the end-to-end suite against a real node and keyed indexer, spawned by the suite on free ports:

```bash
cargo build --release -p ursula --bin ursula
URSULA_BIN=../../target/release/ursula npm run test:e2e
```

## Open a storage

```ts
import { httpTransports, UrsulaStorage } from "@tonbo-io/pi-durable-ursula";

const { log, keyedState } = httpTransports({
  baseUrl: "https://ursula.example.com", // node or gateway
  stream: "pi/harness-1",               // {bucket}/{harness_id}; the bucket must exist
  token,                                 // sent as Authorization: Bearer
});

const storage = await UrsulaStorage.open({ log, keyedState, mode: "fail-if-active" });
// hand `storage` to the Pi harness; call storage.close(...) on shutdown
```

`open` creates the stream if it does not exist and refuses unless the node advertises `keyed-batch-v1`. It then reads the owner metadata through keyed-state, replays the records the projection has not covered yet, preloads the live sessions and tasks, and finally claims the stream by appending an owner record.

Choose the open mode by how the host prevents two owners:

| Mode | Behavior |
| --- | --- |
| `fail-if-active` (default) | Refuses with `OwnershipActive` while the current owner shows activity: its claim is not closed and the log advanced within the last 3 s. A crashed owner costs that wait once. |
| `fence` | Takes over at once. The previous owner gets `FencedError` on its next commit and must not reopen on its own. For supervised workers that hold their own lease. |

Use a unique, never-reused `harness_id` per session. A shape such as `{scope}-{9999999999999 − created_ms}-{ulid}` makes a prefix listing return one scope newest first.

## State store

`stateStore` picks how the owner holds state. `auto`, the default, uses `bounded` when the node advertises `keyed-state-v1` for the stream and `full-resident` otherwise.

- **`bounded`** keeps the commits not yet covered by keyed state (the overlay, capped by `overlayCapBytes`, default 256 MiB) plus a cache of key ranges (`cacheBudgetBytes`, default 64 MiB). A background loop asks keyed-state to catch up and trims the overlay. If the indexer falls behind by more than the overlay cap, commits wait for it.
- **`full-resident`** replays every record at open and keeps the whole state in memory. Use it for tests or a node without a keyed indexer.

## Failures

- A commit that times out or hits a `5xx` is retried with the same bytes under the same `Stream-Record-Match`, after reading record `N` back to see whether an earlier attempt landed. Pi's `StorageRejected` is used only when nothing became durable, for example a commit over 32 MiB or deeper than 127 levels.
- Transient failures on the session path retry for 30 s and then poison the storage; the host reopens. The background flush loop never poisons on a transient failure.
- `FencedError` means another owner claimed the stream. It is terminal for this process.
